## 목표와 작업 범위

- [ ] GET /api/dashboard 응답 타입과 조회 모듈을 만들고 개발용 fixture를 실제 조회로 교체한다.
- [ ] EventSource를 연결하고 ready 및 재연결 때 전체 조회한다. 최초 화면 조회도 수행해 연결 실패 시 데이터를 볼 수 있게 한다.
- [ ] dashboard-changed 수신 시 전체 데이터를 재조회하고 바뀐 행을 잠시 강조한다.
- [ ] 동시 재조회를 합치고 늦게 도착한 이전 응답이 최신 화면을 덮어쓰지 않게 한다. 조회 중 이벤트가 오면 마지막에 다시 조회한다.
- [ ] SSE 연결/재연결/오류 상태와 조회 실패 재시도 UI를 제공하고 컴포넌트 종료 시 연결과 요청을 정리한다. API 조회 캐시는 비활성화한다.

## 완료 기준과 검증

- [ ] 브라우저 두 개에서 외부 POST 요청 후 카드와 순위가 모두 갱신되는지 확인한다.
- [ ] 연결 전후 응찰 누락, 연속 이벤트, 느린 조회 역전, API 재시작 후 복구를 검증한다.
- [ ] 웹 정적 검사와 production build를 통과한다.
- [ ] 선행 티켓이 반영된 최신 통합 브랜치 기준으로 검증했다.
- [ ] 변경 요약과 검증 결과를 아래에 기록하고 작업 내용을 커밋했다.
- [ ] 통합 브랜치에 병합 후 관련 회귀 검사를 확인했다.

## 작업 절차

1. 루트 계획의 worktree 작업 규칙을 확인한다. 001은 worktree 생성 전 초기 기준 커밋이 필요하다.
2. 최신 통합 브랜치에서 위 브랜치와 worktree를 만들고 상태를 IN_PROGRESS로 변경한다.
3. 범위 안의 작업과 검증을 수행하고 결과를 기록한다.
4. 담당 서브에이전트는 결과를 루트에 보고한다. 루트가 최신 통합 브랜치를 반영하고 검증 후 병합한다. 완료 기준을 충족하면 루트가 DONE으로 변경한다.
5. 병합이 확인된 worktree와 브랜치를 정리한다.
