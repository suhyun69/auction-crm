## 목표와 작업 범위

- [ ] GET /api/events를 text/event-stream으로 제공한다. 연결 준비 이벤트 ready와 변경 이벤트 dashboard-changed를 정의한다.
- [ ] 새 응찰 트랜잭션 커밋 후에만 변경 이벤트를 발행한다. 롤백과 멱등 응답 재사용에서는 발행하지 않는다.
- [ ] 단일 API 인스턴스의 구독자를 관리하고 heartbeat, timeout, 연결 종료 시 자원 해제를 구현한다.
- [ ] 이벤트는 재조회 신호로 사용하고 과거 이벤트 재생은 제공하지 않는다. 웹에서 접근할 API 원점과 CORS 설정은 환경별로 제한한다.
- [ ] Spring SSE 타입이 도메인에 침투하지 않도록 이벤트 포트와 어댑터를 기존 계층 규칙에 맞춰 배치한다.

## 완료 기준과 검증

- [ ] 복수 구독자 수신, 커밋 전 미전송, 롤백 미전송, 멱등 재요청 미전송을 검증한다.
- [ ] 종료된 구독자 정리와 연결 복구를 확인하고 ArchUnit을 통과한다.
- [ ] 선행 티켓이 반영된 최신 통합 브랜치 기준으로 검증했다.
- [ ] 변경 요약과 검증 결과를 아래에 기록하고 작업 내용을 커밋했다.
- [ ] 통합 브랜치에 병합 후 관련 회귀 검사를 확인했다.

## 작업 절차

1. 루트 계획의 worktree 작업 규칙을 확인한다. 001은 worktree 생성 전 초기 기준 커밋이 필요하다.
2. 최신 통합 브랜치에서 위 브랜치와 worktree를 만들고 상태를 IN_PROGRESS로 변경한다.
3. 범위 안의 작업과 검증을 수행하고 결과를 기록한다.
4. 담당 서브에이전트는 결과를 루트에 보고한다. 루트가 최신 통합 브랜치를 반영하고 검증 후 병합한다. 완료 기준을 충족하면 루트가 DONE으로 변경한다.
5. 병합이 확인된 worktree와 브랜치를 정리한다.
