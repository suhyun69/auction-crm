## 목표와 작업 범위

- [ ] POST /api/bid와 경계별 DTO, 유스케이스, 도메인 서비스를 구현한다.
- [ ] 경매 잠금 → 멱등 키 조회 → 참가자 조회/생성 → 최고가 판정 → 기록 저장 → 최고가 갱신을 하나의 트랜잭션으로 수행한다.
- [ ] Idempotency-Key는 선택 헤더로 받는다. 동일 키와 동일 정규화 요청은 최초 응답을 재사용하고, 다른 요청이면 409를 반환한다. 키가 없으면 매 요청을 새 응찰로 처리한다.
- [ ] 승인·기각 모두 200, 잘못된 입력은 400으로 기존 오류 형식에 맞춘다. 최초 응답의 highestAmount는 판정 시점 값이며 재요청에서도 유지한다.
- [ ] 정상적인 기각도 저장하고, 입력 검증 실패와 중복 재요청은 카운트에 포함하지 않는다. OpenAPI에 예제를 추가한다.

## 완료 기준과 검증

- [ ] HTTP 응답, 롤백, 동시 최초 응찰, 동일 고객 동시 요청을 통합 테스트한다.
- [ ] 동일 키 동시 요청이 기록 1개만 생성하고, 키 충돌은 409인지 검증한다.
- [ ] 큰 금액·소수·문자열·잘못된 JSON과 기존 API 회귀 테스트를 통과한다.
- [ ] 선행 티켓이 반영된 최신 통합 브랜치 기준으로 검증했다.
- [ ] 변경 요약과 검증 결과를 아래에 기록하고 작업 내용을 커밋했다.
- [ ] 통합 브랜치에 병합 후 관련 회귀 검사를 확인했다.

## 작업 절차

1. 루트 계획의 worktree 작업 규칙을 확인한다. 001은 worktree 생성 전 초기 기준 커밋이 필요하다.
2. 최신 통합 브랜치에서 위 브랜치와 worktree를 만들고 상태를 IN_PROGRESS로 변경한다.
3. 범위 안의 작업과 검증을 수행하고 결과를 기록한다.
4. 담당 서브에이전트는 결과를 루트에 보고한다. 루트가 최신 통합 브랜치를 반영하고 검증 후 병합한다. 완료 기준을 충족하면 루트가 DONE으로 변경한다.
5. 병합이 확인된 worktree와 브랜치를 정리한다.
