# 시나리오 엔진 작업 지침

- 루트가 배정한 티켓과 `simulator/README.md`를 먼저 읽는다. 담당 범위는 명시적으로 배정된 `simulator/` 파일이다.
- `core.mjs`는 가상 시각·결정적 난수·참가자 상태와 응찰 판단만 담당한다. 실제 HTTP, 벽시계 timer와 터미널 제어는 분리한다.
- `scenario.mjs`는 coercion 없이 JSON을 검증하고 이름과 기본값을 정규화한다. 금액은 API와 같은 양의 안전한 정수 범위다.
- `clients.mjs`의 재시도는 같은 논리 요청의 키·본문을 보존한다. 정상 기각과 전송 실패를 혼동하지 않는다. `attempt` 이벤트에 알려지지 않은 결과의 원요청을 남긴다.
- `cli.mjs`가 pause/resume/배속/중지, abort와 결과 파일을 담당한다. dry-run은 API/DB를 호출하지 않아야 한다.
- 예산은 한 경매의 최대 희망 가격이다. 본인 선두에 재응찰하거나 예산을 넘기지 않는다. 시드 재현성은 같은 API 응답 순서를 전제로 한다.
- Node 표준 라이브러리를 우선한다. 테스트는 `npm run test:simulator`로 실행하고 실제 호출 검증은 개발 DB와 분리한다.
- API·웹·Docker 개발 서버의 수명이나 데이터 초기화 동작은 임의로 수정하지 않는다. root package.json·문서·티켓·Git/worktree/병합은 루트 담당이다.
- 별도 지시 없이 하위 에이전트, 커밋·병합 또는 다음 티켓을 실행하지 않는다.
